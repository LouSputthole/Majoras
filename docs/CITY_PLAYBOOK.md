# Clock Town production playbook

Working procedure, 2026-11-08. The city is the priority: retain the actual district shapes and route network, then give them better authored geometry, materials, lighting and exploration. Start with a complete, reviewable South Clock Town example and reuse its validated pipeline for the other districts. Do not expand a broken importer or multiply placeholder buildings across the city.

**Developer handoff after the lockup:** [HANDOFF.md](HANDOFF.md) is the entry point; [FULL_CITY_PLAN.md](FULL_CITY_PLAN.md) expands this procedure into five district briefs, 17 venue/annex packets, shared-system work, file ownership, dependencies and acceptance gates. [MVP_REVIEW.md](MVP_REVIEW.md) reconciles saved editor, route, build and failed visible-player evidence. This playbook remains the reusable technique reference; the full-city plan owns the new assignment queue.

This playbook records reusable project knowledge. [ITERATION_LOG.md](ITERATION_LOG.md) separates observed results, source findings, proposals and rejected directions. [ROM_REFERENCE.md](ROM_REFERENCE.md) is the detailed local source-assembly register; [ASSET_PIPELINE.md](ASSET_PIPELINE.md) and [ART_DIRECTION.md](ART_DIRECTION.md) remain the production art contracts.

## 2. Repeatable district pipeline

| Stage | Work | Output / exit requirement |
| --- | --- | --- |
| 1 — identify source | Hash the supplied local ROM; record version, decomp/tool revisions and the chosen scene/header/time/state | Reproducible source profile. A folder named after an area is not sufficient evidence |
| 2 — region asset index | Read scene XML, room shape/header, actor entries, object bank list and actor initialization/draw code | Complete room/actor/material/collision/portal inventory with omissions and conditional variants |
| 3 — static actor assembly | Import room shape first, then the separate static/posed actor pieces visible in the chosen state | Recognizable source scene with correct pivots and no mixed alternate-day layers |
| 4 — coordinate and collision check | Apply one source→Blender→Unity conversion; compare anchors, bounds, winding and original room collision | Aligned source reference. Record actor collision gaps and provisional meter scale separately |
| 5 — authored material families | Classify surfaces by actual appearance/use, build one representative sample for each family | Portable, readable modern materials with stable IDs and channel/color-space notes |
| 6 — hero and kit refinement | Rebuild landmark silhouettes and construction depth inside the source route envelope | Authored tower/ground/perimeter benchmark, then reusable district kits; no generic substitute town |
| 7 — exploration | Add a bounded Unity exploration profile using validated collision and a controllable modern camera | Named routes traversable with reproducible input; proxy player clearly distinguished from finished Link |
| 8 — same-camera A/B | Render local source and authored candidate from identical camera/state/profile | Visible side-by-side or A/B evidence, retained forms/deviations and a correction list |
| 9 — quality and build | Recheck routes, contacts, material channels, camera motion, console, build and performance scope | Dated candidate evidence; visual approval and runtime correctness reported separately |

Do one vertical pass through these stages before extracting every district. The generalization target is a region manifest plus shared import helpers, not an expanding hardcoded list of unrelated object names. The current South script is a working specialized recipe, not yet that general importer.

### Region index contract

For each district, record the following before import work:

- Scene/XML path, source revision, scene/header selection and room names.
- Room-shape display-list references, collision header and entrance/exit data.
- Actor entry index, masked ID, params, decoded rotation, half-day/cutscene metadata, object bank and visible-state condition.
- Actor-local geometry scale, world translation, initialization pivot shifts, nested/spawned parts and draw-time transforms.
- Static mesh, posed skeletal actor, billboard/effect, runtime-only component or controller classification.
- Materials/textures, combiner/tile state, alpha/culling behavior and approximation flags.
- Imported/omitted/rejected status, source citation and the capture that will verify each recognizable element.
- Portal/source anchor, route clearance and collision ownership, with unknowns explicitly recorded.

Use actor names as a lookup aid, not as truth. The actual South default entry, params and draw/init behavior determine which Business Scrub is present; multiple merchant actor implementations exist. A friendly English description or a raw list of all object-bank display lists is not a reliable asset assembly recipe.

### Static assembly rules learned in South

1. Import the actual room shape. Tower masonry is in the room; the clock face/ring/center, gears, counterweight, closed panel, doors and platform pieces are separate actor geometry.
2. Use the normal base header for the selected reference profile. Alternate room headers and half-day masks select different candidate sets; do not stack all variants.
3. Decode packed actor entries before transforming geometry. `Actor_SpawnEntry`, half-day flags and params matter. Actor scale is not world unit scale.
4. Reproduce initialization changes and spawned pieces. South's two door leaves have distinct shifted pivots, even though the scene initially lists one spawning actor.
5. Respect component-local transforms. The sun/moon panel is below the face center and inherits the correct face transform; clock time alone does not determine the counterweight's elapsed-frame phase.
6. Keep invisible/unused/off-scene pieces out of the chosen assembly. A symbol existing in an object XML does not mean it is visible in this district/state.
7. Skeletal limbs and effects need their own reconstruction. Do not pile raw limb display lists at the actor origin or turn a camera-facing smoke effect into arbitrary static geometry.

## 3. Coordinate, collision and extraction discipline

The existing reference interchange uses Unity `(x,y,z) = N64 (x,y,-z)/100`. The source Blender actor conversion is `(x,-z,y)/100`; exporter conversion and mirrored winding complete the Unity mapping. Check the current code before reusing the formula in a new consumer. Do not add a second flip or divide actor world positions by their geometry scale.

Store the source coordinate frame and the proposed authored manifest frame explicitly. The older authored proxy uses a north/east semantic convention; the ROM conversion is a source-axis mapping. A rotation/translation tying those frames together must be surveyed rather than inferred from matching axis names. Use landmark anchors to register them before replacement meshes inherit proxy placements.

Preserve original room collision as a separate mesh and preserve unparsed surface metadata as source data. The current import bypasses incomplete MM→OOT enum interpretation; this is preferable to assigning incorrect OOT surface semantics. It does not implement MM collision behavior. Actor collision, interaction volumes, ledge rules, slope/step limits and transition triggers need separate implementation and checks.

Before accepting each region:

- Verify source bounds and at least three widely spaced known anchors, including elevation.
- Check face orientation, normals, UV orientation, winding and asymmetric props.
- Raycast entrance ground points, then perform real movement routes; a ground raycast is not a controller test.
- Keep render/collision layers distinct, with no invisible leftover proxy floor or overlapping imported ground.
- Confirm pivots/contact for doors, posts, platform bases and every replaced kit piece.
- Check old and new art from moving cameras for coplanar flicker and apparent floating contact.

The current extraction command and local paths are documented in [tools/reference/README.md](../tools/reference/README.md). Generalize only after the new region index is complete. This planning step indexes North/East/West XMLs; it does not extract or import them.

## 4. Reusable authored material library

The local source reference has 158 material records, 108 exported texture images and 316 Unity sampler-specific texture assets in the recorded run. Those are source-conversion counts, not the desired number of modern authored materials. Group the modern city by material family and purposeful variants; do not create a unique PBR shader for every source combiner state or a single gray material for the whole town.

Current MVP progress is partial: `stone_bricks` replaces source PNGs `052`/`097`, `plaza_pavers` replaces `041`, `wall_relief` replaces `057`, and `golden_pavers` replaces `037`. Four AI-assisted repaint files affect 33 texture slots. Texture+wrap deduplication yields 149 enhanced sampler assets, with mipmaps, trilinear filtering and anisotropy 8. The original N64 UV basis/tile dimensions stay fixed even when replacement artwork is 1254 pixels wide; actual image texel size affects relief-neighbor sampling only. Preserve source graphic identity and inspect seams rather than treating higher resolution as automatic approval.

The current candidate layers the source combiner's color/UV logic into a Built-in Standard surface shader with real lighting/shadows, plus a separate sky shader. A small stone/ground repaint pass and plain wood/metal architectural materials exist. **All six authored material families are not finished**: plaster and cloth remain source treatment, and the full portable PBR-map library remains future production work. Ten additional renderers add approximately 8,000 triangles; the underlying 21 source renderers and 158 material records remain the structural baseline.

Proposed IDs below are a future catalog convention. Create only families supported by actual district surfaces; “plaster” is not permission to repaint every original masonry wall.

| Family / proposed root | Preserve | Modern authoring and variation | Acceptance view |
| --- | --- | --- | --- |
| Stone — `city.mat.stone` | Warm ochre/mossy body, broad blocks, deep joints and strong caps/reveals | Modeled silhouette/caps/important joints; restrained normal detail; shared stone trim plus moisture/paint masks; avoid neutral-gray castle replacement | Tower base, wall corner and north-facing shaded facade in flat/day/night light |
| Plaster — `city.mat.plaster` | Only source-confirmed rendered/infilled surfaces and broad painted color masses | Rough plaster body, modest edge wear, underlying construction where visible; tint masks within approved palette | Facade beside adjoining stone/timber to prove actual family separation |
| Wood — `city.mat.wood` | Dark structural timber, painted construction faces and readable grain grouping | Thick beam ends, joinery and caps in geometry; shared plank/beam trims; painted/unfinished variants without uniform procedural grime | Platform underside/posts, stall rear and ground contacts |
| Cloth — `city.mat.cloth` | Saturated banner rhythm, canopy shape, sag and graphic motifs | Real thickness/hem where close; conservative cutout; low-frequency fabric normal; shared color/graphic atlas; wind only after anchor/shape approval | Banner row, canopy underside and distant mip edge; check alpha/culling |
| Metal — `city.mat.metal` | Clock's graphic hierarchy and accent colors, fasteners/brackets where sourced | Moderated rough metal response, painted metal variant, readable bevels; avoid mirror chrome or photoreal rust noise | Clock face/gear close-up and tower approach at intended exposure |
| Ground — `city.mat.ground` | Original paving pattern, route color grouping, level changes and compression | Pattern-preserving tile/trim, curb geometry, subtle displacement/bump; wear follows surveyed traffic; no extra stairs or enlarged plaza | Low approach, top-down plan and moving camera over material joins |

Thatch/roof treatment may become a separate material family once the source index justifies it. Keep thatch volume and silhouette in geometry; thin noisy alpha cards are not an automatic improvement. Civic paint/sign graphics can share family masks/atlases while retaining region identity.

For every family, retain editable sources, base color, normal, roughness/metal/occlusion channels and channel-packing notes. Base color is sRGB; other maps use explicitly declared data settings. The source N64 combiner shader is a reference renderer, not the production PBR library. Its color-space/tile semantics must not be copied blindly into authored materials.

Approve one representative cluster under neutral light and the intended daytime/nighttime profiles before multiplying variants. Review at the actual exploration camera distance: detail that reads only in a beauty close-up is low priority. Structural bevels and contact must be visible with textures disabled.

## 5. Hero refinement order

1. Freeze a source-backed composition strip: tower approach, reverse square, rear/north approach, east/west thresholds and platform access. Keep source room and candidate available independently.
2. Rebuild the clock/tower hero assembly: primary mass/cap, face graphic organization, separate mechanism pivots, masonry depth, door leaves and closed access panel. Preserve opening envelopes for later animation.
3. Rebuild ground and perimeter as one route-preserving benchmark. Improve corners, parapets, reveals, trims and ground transitions before adding small clutter.
4. Rebuild Day 1 construction platform/stalls with grounded posts, supported canopies, joints, dimensional boards and source-backed painted panels.
5. Apply approved material families; add banners/fixtures and local wear only after silhouette and route checks pass.
6. Add source-correct sky/moon/effect presentation when their state/camera rules are understood. Do not use dramatic fog or a giant generic moon to hide missing architecture.
7. Expand to more districts using proven kits, with region-specific facades, proportions and graphics. Reuse construction techniques and materials; preserve each original district's actual shape.

A subdivided original low-poly mesh with sharpened textures is still a reference-derived treatment, not proof of authored modern architecture. A procedural primitive village with richer lighting is also insufficient. The acceptance target is recognizable city geometry with purposeful new construction detail that survives wireframe, flat light, gameplay distance and original/candidate A/B review.

### Comparison protocol

- Store camera transform, lens, aspect/resolution, scene revision, render profile, day/time and visible-state selection.
- Capture **A: imported local source reference** and **B: authored candidate** at the same stored pose. Label the baseline's approximate combiner lighting/filtering and any camera mismatch to original hardware footage.
- First use neutral/flat lighting to judge shape and palette; then the intended lighting to judge the experience. Different dramatic lighting cannot conceal a geometry mismatch.
- Show actual on-screen A/B or side-by-side output, not two unrelated attractive screenshots. A third crop/wireframe panel can prove structural changes.
- Include one moving-camera clip at near ground/props and one tower-approach route. Static images can miss flicker, floating supports, camera clipping and LOD popping.
- Record retained landmarks, deliberate deviations, regressions and the next bounded correction. Preserve failed evidence rather than replacing it without a note.

Exit requirements for the first visual MVP: district routes/scale remain intact; tower face and silhouette retain identity; new structural detail is visible; material families read distinctly; prop contacts are grounded; no broad missing textures or UV scaling errors; source/candidate comparison is reproducible; actual runtime checks are recorded. “More polished than boxes” is not the visual bar.

## 8. Iteration rhythm and quality/build checks

For each pass: select one visible defect or bounded system gap; capture the before state; state a hypothesis; make the change; capture the same viewpoint/route; inspect actual output; run affected checks; log result and next action. Prefer a real small improvement over adding unverified breadth.

Use [ACCEPTANCE.md](ACCEPTANCE.md) for detailed case IDs. Every city pass should at least cover:

1. Import/schema: no missing files, dangling materials, invalid arrays, nonfinite data, unexpected mesh counts or silently approximated unsupported material inputs.
2. Space: known anchors/bounds/collision agree, routes remain open and correct, no duplicate source/proxy floors.
3. Art: tower/region silhouette, palette, structural geometry, grounded contact, UV scale, alpha edges and moving-camera depth stability.
4. Exploration: input, safe spawn, walk/turn, camera orbit/recenter/collision, pause and out-of-bounds recovery for the actual enabled scope.
5. Runtime: compilation/console, Play Mode advancement, screenshot/video of the current scene and explicit omissions.
6. Build: package the current candidate, run it, repeat the critical route/camera comparison; an older proxy build is not evidence for a new reference/modernized scene.
7. Performance: record named machine, resolution, preset, frame-time distribution and memory when measuring. Scene statistics alone do not qualify performance.
8. Repository boundary: no ROM, extracted/reference assets, saves, local credentials, caches or generated builds in tracked changes.

Source inspection, editor execution, packaged runtime, visual comparison and user approval have different evidence. The log must name which occurred. Preserve current work and verify after the final source edit; never carry an older pass forward across untested importer/shader changes.
